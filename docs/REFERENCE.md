# Sketchy reference

Detailed notes on how things work. New here? Start with the [README](../README.md).

## Modelling tools

| Tool | Notes |
|------|-------|
| Sketch | Plane (XY/XZ/YZ + offset) or any flat body face. Line, **Path** (open polyline), rectangle, circle, polygon; snap grid; edit values numerically. Nested shapes become holes |
| Extrude | New / Join / Cut / Intersect / **Auto (cut or join)**; extent *Distance*, *Through all*, *To object* (bounding-box based); symmetric, **draft/taper angle**, twist, top scale |
| **Thin extrude** (Extrude dialog, Type) | Extrudes only a wall of a set thickness around each closed profile: inside, outside or centred on the outline. Not combined with taper |
| Revolve · **Sweep** · **Loft** · **Coil** · **Rib / Web** | Sweep follows an open path of lines, arcs and fit-point splines (optionally smoothed); its **Corners** option is *Swept* (the default, the profile carried round each corner) or *Mitred* (each straight segment cut at the plane bisecting the corner, full width kept; lines only); loft blends 2+ profile sketches; coil is a helical solid; rib thickens an open path |
| **Hole** | Simple, counterbore, countersink, through-all, optional internal thread. Place by clicking a face |
| **Thread** | Real helical groove (external or internal, left/right-handed) cut into a body |
| **Press/Pull** | Click a flat face and drag it in the viewport (or type a distance) to push or pull it |
| Fillet · Chamfer | On picked edges or faces. Fillet can have a **variable radius** (start and end radius, optionally swapped), and **Whole loop** extends the pick along the connected edges that run around the same face |
| **Shell** | Hollow a body to a wall thickness (inside, outside or centred), optionally opening picked faces |
| **Scale** · **Split Body** | Uniform / non-uniform scale (non-uniform is exact for a box, cylinder, sphere, cone or a plain extrude that has not been changed since; otherwise curved faces become facets and the feature warns); split by plane or by another body |
| Combine · Move/Copy · Mirror · Remove | Click bodies in the viewport to fill body fields |
| **Pattern** | Linear, circular, **along a sketch path** or **on a face** (grid on the picked plane) |
| **Text · Insert SVG · Insert DXF** | Sketch tools: text uses real Roboto outlines (counters become holes); SVG (paths, shapes, transforms, curves flattened) and DXF (LINE/ARC/CIRCLE/LWPOLYLINE/POLYLINE, touching segments joined, `$INSUNITS` honoured) are scaled to mm and centred. Also drag a `.svg`/`.dxf` onto the viewport |
| **Interference** · **Drive Joints** · **As-built Joint** | Lists overlapping body pairs with volume; sliders move revolute/slider/cylindrical/planar joints; as-built keeps both bodies where they are |
| **Units** | File → Document units (see the menu for the list). Geometry stays in mm; fields, measure and properties convert |
| **Mesh repair** | Non-watertight STLs are welded, de-duplicated, re-oriented and hole-filled on import; the toast says what was fixed |
| **Clicking in the model** | A plain click selects a **face** (flat faces highlight under the pointer); an edge near the pointer wins over the face, so you can pick edges to fillet or chamfer. A click on a curved face selects its whole body, and **double-click** selects the whole body anywhere. Choose body priority in the Select menu (the Select button) if you would rather a click always take the whole body; the choice is remembered. The Browser tree always selects bodies. Window, freeform and paint selection take whole bodies |
| **Camera moves** | Fit, Home, Zoom Window, the ViewCube and starting a sketch glide to the new view over a fraction of a second (dragging the view cancels the move). Opening a design jumps straight to it. Making a body, a feature or opening a dialog never changes the zoom or angle of the view. The sketch grid is deliberately faint, and the shape you are drawing is a thick bright line (white on the dark theme, near-black on the light one) so it always stands out; finished sketch shapes are thick blue lines |
| **Search** (magnifier in the top bar, or `S`) | Opens a field to the left of the button. It matches commands by name and, when you're signed in, your saved designs by name or folder (designs are listed first, under their own heading). Arrow keys move through the results, `Enter` runs the command or opens the design (jumping to its tab if it's already open), and `Esc` closes the field |
| **Accounts and Server settings** (administrators: your initial → Server settings) | The page opens on **sign in**. It only opens on sign-up for the very first account on a new server, which becomes the administrator. Sign-up is then **closed** until an administrator ticks **Allow new people to register**. Administrators can add people under **Users** (leave the password blank to generate a temporary one, shown once), reset passwords, grant or remove admin, and delete users. **Sign-in protection** locks an address, and the username being tried, out after a set number of failed sign-ins within a set time, for a set time (default 5 failures in 15 minutes, locked for 15; 0 failures switches it off). Locked addresses and usernames are listed there with an **Unlock** button, and the lock-outs reset when the server restarts. Behind a reverse proxy the real address comes from the `X-Forwarded-For` or `CF-Connecting-IP` header, trusted only when the request arrives from a private or loopback address |
| **Utilities tab** | **Export** opens one dialog for every supported format: STL, 3MF (with body colours), OBJ, STEP (exact: true planes, cylinders and fillets) and the Sketchy project file (the whole timeline, reopens fully editable). Choose all visible bodies or only the selected ones, and name the file. **Printer…** picks the printer (or a custom size) and **Show Build Volume** draws its build volume in the viewport; Properties reports whether each body fits. Export is also in the File menu |
| **Naming, autosave and versions** | Every design is named when you create it: **New design** (the + tab, Ctrl+N or the sidebar button) asks for a name and a folder in an in-app dialog and stores the design straight away. From then on Sketchy **autosaves** to the server a couple of seconds after each change; the tab's `*` shows unsaved changes and its tooltip says Saving, Saved or the problem. Autosave updates the design in place and does not add a version. **Save version** (Ctrl+S) adds a version to the history (restore them from the V1 ▾ button in the sidebar); **Save As** stores a copy under another name or folder. If you dismiss the first dialog the design stays Untitled and asks for a name once, at its first edit. If the design was changed on another device, autosave pauses and a banner asks what to do. On the next start Sketchy reopens the design you were last in, and restores any change that hadn't reached the server. The **Designs** sidebar on the left shows your folders and designs: expand or collapse folders, drag a design onto a folder, click the pencil beside a name to rename, use the version button for history, a design's **⋯** menu to move or delete it, and a folder's **⋯** menu to create, rename, move or delete folders. Search shows matches from every folder. Design names are unique across your account. Sketchy no longer uses browser prompt, confirm or alert popups (the one browser-controlled dialog left is the "Leave site?" warning when closing the window with unsaved work). Designs are stored as `.json` project files that keep the whole feature timeline, so they stay editable. STEP, STL, 3MF and OBJ are export formats and cannot be reopened as editable designs |
| **Export** | STL, **3MF** (with body colours), **OBJ**, and **STEP** — exact (AP242, true planes, cylinders and fillets); an imported mesh is written as the faceted solid it is |
| **Joint** | Rigid, revolute, slider, cylindrical, planar and ball joints positioning one body relative to another |
| **Parameters** | Name dimensions (`width = 40 mm`) and use expressions in any numeric field (`width/2 + 3 mm`, `sin(30)*r`). Changing a parameter rebuilds the whole timeline |
| **Section Analysis** (Inspect tab) | Clip the model with up to three planes or a box; the cut faces are capped. A plane is an origin plane (XY, XZ, YZ), a construction plane or a flat face picked in the view. Each has an offset along its normal (a number or an expression, so it follows parameters), a flip side and its own Show switch; drag the arrow in the view to move it. **Box** is six planes (centre and half sizes, each face has its arrow) and replaces the planes. Closing the panel keeps the cut: an **Analysis** row in the Browser reopens it, hides it, and Remove ends it. View-only, not stored in the design or the timeline; opening another design clears it |
| **Surface tab** | **Extrude**, **Revolve**, **Sweep** and **Loft** make open surface bodies (listed under *Surfaces* in the Browser, shown in light blue; closed or open sketch shapes both work). **Stitch** joins surfaces, and a closed shell becomes a solid; **Thicken** turns a surface into a solid by offsetting it along its normals. **Trim** cuts a surface at a plane (XY/XZ/YZ or a construction plane, with offset) and keeps one side. **Extend** grows a surface outward from every open edge by a straight tangent strip. **Pipe** makes a solid or hollow tube along a path sketch |
| **Mesh tab** | **Insert Model** imports STL, OBJ, 3MF and STEP files (also by dragging a file onto the model). Meshes are repaired automatically; a file with several objects becomes several bodies, and 3MF colours carry over. STEP import reads solids made of planes, cylinders, cones, spheres and tori with line, circle, ellipse and B-spline edges, and the faceted solids Sketchy writes; faces on free-form (B-spline) surfaces can't be read and are reported, and the gap they leave is closed flat. STEP units are converted to millimetres. **Shell** and **Combine** work on any body, imported or modelled. **Reduce** lowers a body's triangle count to a target percentage within a maximum deviation. **Separate** splits a body made of disconnected pieces into separate bodies | **Clean Mesh** welds nearly coincident vertices and drops stray fragments from a mesh body. If a file isn't watertight when imported, a repair dialog offers to weld and fill holes |
| **Sketch patterns** | In the sketch Modify menu, **Rectangular Pattern** and **Circular Pattern** repeat the selected shapes by count and spacing (or count, angle and centre) with a live preview |
| **3D Sketch** | Create menu (Solid and Surface). Picks points in 3D to make a path (optionally closed or smoothed) that Pipe, Sweep and other path-driven features can follow |
| **Appearance and Render** | **Appearance** assigns a material (printing plastics, metals, glass) or custom colour to a body; the material's density drives the mass in Properties. **Render view** (Display menu) adds reflections, shadows and removes the grid, and **Save Image** exports a PNG at a chosen size and background |
| **Print Check** | Utilities tab, Printer group. Opens with a plain verdict ("Ready to print", "Printable, with a few things to know" or "Needs changes before you print") and a short list in everyday words: does each body (and all of them together, by shelf packing) fit the selected printer's bed; do overhangs steeper than a limit angle (default 45°) need supports, with a **Lay it that way** button that adds Move features to stand the part on its best face; and are walls thicker than three nozzle widths (checked automatically; thin spots are marked in red, and a few sharp tips under 1 % of the samples are not counted). It also gives a rough weight and filament length for the chosen material |
| **Print Setup** | Utilities tab, Printer group (and Settings). Printer, nozzle size, layer height, material, and a fit gap (Tight 0.1, Normal 0.2, Loose 0.3 mm per side). Kept in the browser, and optionally added to the design as the parameters `nozzle`, `layer` and `tol`, so a field can say `5 mm + 2 * tol`. Print Check and the templates read them from the design |
| **Templates** | Utilities tab, Learn group (and the end of the guided tour). Box with lid, phone stand, cable clip and shelf bracket: ordinary designs built from primitives and Combine, with a **Customize** panel of sliders (Browser, Document Settings, Customize sliders). They use `tol` for the lid lip and screw holes and `nozzle` for wall thickness, so they print right on the person's own printer |
| **Start making with your LLM** | The third tile of the welcome card, and Utilities tab, Learn group (**Connect an AI assistant…**). Opens Account → AI assistants: the server address, tokens and a step-by-step guide for Claude, ChatGPT and others. When the window is closed the welcome card comes back. Not available when you are not signed in to a server or the administrator has switched MCP off |
| **Welcome card** | The first page of an empty design (nothing else opens before it; the design is named after you choose): **Welcome to Sketchy, what would you like to do today?** with three tiles. **Make my first part** shows the New design window, then the seven-step guide. **Import an existing model file** shows the New design window, then the file chooser and the import's own steps. **Start making with your LLM** opens the assistant setup. The × hides the card for good and asks for the design's name. No window ever opens over another. The 23 MB modelling engine starts downloading when the page loads, so it arrives while you sign in and choose; until it is here the card shows "Getting the modelling engine ready… 14.2 of 21.9 MB" with a bar, and the guide's first step waits ("Getting ready") and starts by itself the moment the engine is ready |
| **Make my first part** | A seven-step guide from a sketch to Print Check and Export. It highlights the real button for each step and moves on by itself when the step is done; it can be skipped at any time |
| **Undo history** | The arrow beside Undo (or a right-click on it) lists the last 20 changes in words ("Added Extrude1", "Changed parameters") and goes back to before any of them in one click; Redo brings them back |
| **Touch screens** | Tablets work for viewing and modelling: one finger orbits, two fingers pan and pinch-zoom, tap selects, double-tap picks a whole body, and a long press opens the context menu. While sketching, one finger draws and two fingers still move the view. A floating bar adds Multi-select, Undo, Cancel and Done in place of the keyboard. Controls grow to touch size, and panels become bottom sheets on narrow screens. Phones can view and measure, but precise sketching is best on a tablet or larger |
| **Sketch: Mirror · Trim · Fit Point Spline · Project / Include** | **Mirror** copies shapes across a picked line or a sketch axis (rectangles stay rectangles for horizontal and vertical lines). **Trim** removes the part of a line, arc, circle or rectangle edge between its nearest intersections (previewed in red). **Fit Point Spline** draws a smooth curve through clicked points; click the first point to close it. A spline is one B-spline edge in the exact kernel: closed ones extrude, revolve, loft and sweep as true curved faces, open ones close a region together with lines and arcs, and open ones are sweep and pipe paths. **Include** copies a model edge, or with Shift every edge of that body, onto the sketch plane as a static copy |
| **Offset Plane** (Construct) | A construction plane offset from XY/XZ/YZ or from another plane. Sketches can sit on it and follow it when you change the distance |
| **Emboss** | Raise or engrave a sketch (text, SVG, shapes) on a face, to a depth |
| **Draft** | Tilts picked flat faces by an exact angle about a neutral plane at the start or end of the body, along a pull direction. Material is cut away or added between the face and its tilted plane, so neighbouring faces stay flat |
| **Thicken Face** (Modify menu) | Adds (outward) or removes (inward) a slab of a set thickness on picked flat faces |
| **Replace Face** (Modify menu) | Moves a picked flat face onto a plane (XY/XZ/YZ or a construction plane, plus offset), growing the body to the plane or trimming it back. The plane may be tilted relative to the face |
| **Boundary Fill** (Modify menu) | Makes a solid from the empty space fully enclosed by the picked tool bodies (including cavities with other bodies inside), or from the region where all the tools overlap. Tool bodies are kept unless you turn that off |
| **Offset Face** | Moves a flat face along its normal (the same tool as Press/Pull) |
| **New Component** | Group bodies into a named component in the Browser (hide, show, select and delete as a group). A joint between bodies of different components moves the whole component of the first body; a joint within one component is refused |
| **Configure Design / Configure Settings** | Define named configurations (sets of parameter values) in a table, then switch the active one. Blank cells use the default |
| **Insert Design / Insert Configured Design** | Copy another design's bodies (from an open tab or your saved designs, optionally in one of its configurations) into this one as meshes. A snapshot: later changes to the source are not carried over |
| **Canvas** (Insert) | Place a reference image on a plane to trace over, with width, position and opacity controls |
| **Measure** (Inspect tab) | Distance (vertex snap), angle, edge length (detects circles), angle/distance between faces |

**Tabs:** every open design is a tab. **+** opens a blank design in a new tab, designs opened from the sidebar get their own tab (an already-open design is just focused), and each tab keeps its own undo history, view and hidden bodies. Closing the last tab leaves a fresh blank design.

The UI uses a conventional parametric-CAD layout: application bar with design tab, `DESIGN ▾` workspace menu, workspace tabs with icon-only toolbar groups (click a group label for its full dropdown), floating Browser card, ViewCube with clickable faces/edges/corners, navigation bar, a timeline of feature icons, a Data panel (grid icon) listing your saved designs with thumbnails, and a right-click **marking menu**.

* **Selection tools** (Select menu) — *Click* (default; drag orbits). *Window*: drag a rectangle, left to right selects bodies fully inside, right to left any body it touches. *Freeform*: drag a loop around bodies. *Paint*: drag across bodies. `Shift`/`Ctrl` adds to the selection, `Esc` returns to click selection. They select whole bodies (body priority).
* **Two Views** (Viewports menu, bottom bar) — Horizontal (stacked) or Vertical (side by side). Each view orbits, pans and zooms on its own; the one under the pointer is outlined and is the one the ViewCube and view tools act on. Sketching and the move gizmo temporarily use one full view.

Shortcuts: `F2` rename · `Enter` accepts a dialog · `S` command search · `E` extrude · `Q` press pull · `F` fillet · `M` move/copy · `H` hole · `J` joint · `I` measure · `L`/`R`/`C` line/rectangle/circle in a sketch · `Del` delete · `Ctrl+Z / Ctrl+Shift+Z` undo/redo · `Ctrl+S` save · `Ctrl+N` new · `Esc` cancel.

### Editing experience

* **Sketching** — every closed region becomes a shaded **profile**; click inside regions in the Extrude/Revolve dialog to pick which ones (a circle inside a rectangle is a hole by default). Tools: line, open path, rectangle, centre rectangle, rounded rectangle, circle, ellipse, slot, polygon.
* **Arcs** — the 3-point **Arc** tool, and in the Line / Open Path tools press `A` for a **tangent arc**. Lines and arcs that meet end to end automatically form a closed, selectable profile.
* **Parametric dimensions** — click a shape in the Select tool and type an *expression* in any dimension label (`width/2`, `hole + 0.2 mm`); it follows your named parameters, so changing a parameter reshapes the sketch. The **Sketch Dimension** tool (`D`) jumps straight to a shape's dimensions.
* **Constraints** — Horizontal, Vertical, Coincident, Concentric, Equal, Parallel and Perpendicular. Pick two items (the first one moves) and the relation is kept through edits and parameter changes; a badge marks each one (click to delete) and the palette lists them.
* **Offset and Fillet** — offset a closed shape by a typed distance (negative goes inward); round a corner of a rectangle or path with a typed radius.
* **Type while you draw** — after the first click, a dimension box shows live values; type a number, `Tab` to the next field, `Enter` to commit (width/height, diameter, radius, length/angle, corner radius…). Expressions and parameters work.
* **Inference snapping** — endpoints, midpoints, centres, quadrants and the origin snap with markers and dashed alignment guides; the grid step adapts to zoom; hold `Ctrl` to snap to nothing.
* **Select tool** (`Esc` in a sketch) — hover/click shapes, drag to move, drag handles to resize, click a dimension label to type a value, arrow keys nudge.
* **Extrude** — translucent blue (join/new) or red (cut) **preview**, an on-canvas **arrow manipulator** to drag the distance, a value box you can type into, operation icons, direction/extent options; `Enter` accepts. The last extrude distance is remembered.
* **Fillet / Chamfer on edges** — hover any model edge (it turns blue), click to select it (red), `Shift`/`Ctrl`-click to add more, then press `F` (or right-click → Fillet / Chamfer). Or select a **face** (Face priority) and Fillet/Chamfer rounds its whole perimeter. Drag the on-canvas arrow or type the radius/distance; `Esc` clears the selection.
* **Selection priority** (SELECT ▾) — *Body* or *Face*. In Face priority hover highlights flat faces; select one first and `Q` (Press/Pull), `E` (pull the face), `H` (hole) or Create Sketch act on it.
* **Timeline** — drag items to reorder (blocked if a feature depends on another), `Ctrl`/`Shift` multi-select, right-click for Edit / Rename (`F2`) / Roll back / Suppress (dependents are suppressed with it, and restored together) / Delete.
* **Browser** — right-click bodies for Rename, Hide, Isolate, Appearance colours, Properties, Delete; hovering a body row highlights it in the model.
* **Navigation** — middle-drag pan, `Shift` + middle-drag orbit, double-click middle to fit, mouse wheel zoom; left-drag also orbits.


## AI assistants (MCP)

Sketchy runs a [Model Context Protocol](https://modelcontextprotocol.io) server at `/mcp` so Claude, ChatGPT or any MCP client can build designs for you.

1. Sign in, click your initial → **Account** → **AI assistants (MCP)** → **Create token**. Tokens belong to your account only, are shown once, and can be revoked there. (Admins can switch MCP off for the whole server under **Server settings**, or set `ALLOW_MCP=false`.)
2. Open the **Set up your assistant** section on the same page. It has a collapsed, step-by-step guide written for each assistant on its own, with your token filled in once you have created one. **Claude** (web and desktop app), **Claude Code** and **ChatGPT** come first, then Gemini CLI, Cursor, VS Code (GitHub Copilot) and a generic entry for any other MCP client.
   * **Claude** (website or desktop app): Settings → Connectors → **Add custom connector**, name it Sketchy, paste `https://your-host/mcp`, click **Add**, then **Connect**. Sketchy opens: sign in (and enter your two-step code if you use one) and click **Allow**. No token needed. The connection then appears under Account → AI assistants as a *connected app* you can disconnect.
   * **ChatGPT**: Settings → Connectors → Advanced settings → Developer mode, then **Create**: name it Sketchy, paste the same URL, set authentication to **OAuth**, and approve in the window that opens.
   * Claude and ChatGPT call Sketchy from their own servers, so they need a public **https** address (see [HTTPS.md](HTTPS.md)). Other tools (Cursor, VS Code, Gemini CLI, Claude desktop with `mcp-remote`) use a token you create under Account. Tokens are accepted **only** in the `Authorization: Bearer` header (never in the address). Connected apps get an access token that lasts an hour and is renewed automatically; reusing an old refresh token ends the connection. A token that keeps hitting its rate limit or sending work that times out is paused until you resume it, and browser pages are refused unless the admin lists their origin in `MCP_ALLOWED_ORIGINS`. See [SECURITY.md](SECURITY.md).
3. Ask it to build something: *"Make a 60×30×8 mm bracket with two 10 mm holes, call it Bracket"*.

Tools (31, defined in `mcp-defs.js` from the same tables the app uses, so they cannot drift from the app):

* **Designs:** `list_designs`, `create_design`, `duplicate_design`, `get_design`, `describe_feature_types` (every feature kind with its fields), `describe_sketch` (shapes, line types, constraints).
* **Editing:** `add_feature`, `update_feature`, `edit_sketch` (add, remove or replace shapes and constraints without resending the sketch), `delete_feature`, `move_feature`, `set_parameters`, `set_appearance` (material, colour, texture on bodies or one flat or curved face), `set_units`, `undo_last_change`.
* **Looking:** `render_view` (a PNG from any angle, with a section and highlighted faces: `section` is an axis and offset, or an origin and normal with an optional offset along the normal, `sections` takes up to six planes at once, `section_box` a centre and half sizes; a plane through a face from `find_faces` is its point and normal with a negative offset), `inspect_design` (with mass and face counts), `find_faces` and `find_edges` (pick by description: "the top face", "the vertical edges", then pass the returned `ref` to fillet, chamfer, shell, hole and so on), `measure`, `print_check`.
* **Versions and files:** `save_version`, `list_versions`, `compare_versions`, `restore_version`, `export_model` (STL, 3MF, OBJ, STEP; the result reports `step_exact`), `export_stl`.
* **Requests from the app:** `list_requests`, `complete_request`.
* **Heavy designs:** a request does not rebuild a design from nothing. The worker first reads the design's saved kernel cache (written by the app or by an earlier request), builds the rest in pieces from where that cache has it, and saves what a long build reached every few seconds, so a request stopped at the time limit (`MCP_TIMEOUT_SECONDS`, 20 s) leaves its progress behind and the next attempt carries on from there. A design that took more than 20 s from scratch is answered in a few attempts, and then in milliseconds; an assistant's own edits rebuild only what they touch. Only one step longer than the limit by itself needs the limit raised.
* **The running app:** `get_live_context` (the open design, what is selected, the view, and the section cut on screen) and `show_in_app` (turn the person's view, select something, show a note, put a section cut on their screen with `section`, `sections` or `section_box`, and take it off with `clear_section`). Any tool that takes a design also accepts `"@current"`, meaning the design the person has open. The page reports this every minute and whenever the selection changes; the server forgets it after 3 minutes of silence.

The server replays the design with the same modelling kernel the app uses, so every call returns the real bodies, sizes, volumes, errors with a hint for each, and a summary of what the change did. A change that would break the model is rejected rather than saved, with the list of problems. Edits change the design in place (no numbered versions; `save_version` or the Save button makes one). The server also offers **resources** (`sketchy://design/{name}` and `.../preview.png`) and **prompts** (design for printing, make parametric, review a design, fix errors, work through requests).

**In the app:**

* **Live changes.** When an assistant changes the design you have open, it updates on screen as it happens, the features it touched pulse in the timeline and carry a small dot (the dot goes away once you edit that feature yourself). If you have unsaved changes or a dialog open, you get the usual "updated elsewhere" bar instead of a surprise reload.
* **The assistant chip.** While an assistant is changing something, a chip at the top says what it is doing, with a **Stop** button. Stop makes the server refuse every change until you press **Resume** (looking still works, and the assistant is told to stop and ask you). Stop lasts at most 30 minutes.
* **Ask the assistant** (the sparkle button at the top right). Write a request, optionally with your current selection (a face, body, edges or features); it waits in a list, and your assistant picks it up with `list_requests` (its instructions say to do that at the start of every conversation, or ask it to "check my Sketchy requests"). Its reply appears under your request. Assistants cannot be pushed to work: they act when they are connected and asked.



## Add-ins (UTILITIES, ADD-INS)

**Scripts and Add-Ins** (UTILITIES, ADD-INS) lists the add-ins you can run, with their description, author, licence and **permissions**, a **Run / Stop** button, **Enabled** and **Run on startup**. **+ Add…** installs one from a zip file or a folder; **Remove** deletes one you installed. Add-ins can add import formats, export formats and commands. Add-ins you install are kept on your account (or in this browser when there is no server); an admin can switch installing off (Account, Server settings, or `ALLOW_ADDINS=false`).

**Fusion 360 add-ins cannot run in Sketchy.** They are Python or C++ programs written for Autodesk's own API. Sketchy add-ins are small JavaScript packages that use Sketchy's API.

**A package** is a folder or zip with `manifest.json` and a few text files (`.js`, `.json`, `.md`, `.txt`, `.css`, `.html`; at most 40 files and 4 MB):

```json
{
  "id": "openscad", "name": "OpenSCAD import and export", "version": "1.0.0",
  "description": "...", "author": "...", "license": "MIT", "main": "main.js", "runOnStartup": false,
  "permissions": ["document.read", "geometry"],
  "contributes": {
    "importers": [{ "id": "scad", "label": "OpenSCAD script", "extensions": ["scad"] }],
    "exporters": [{ "id": "scad", "label": "OpenSCAD script", "extension": "scad" }],
    "commands": [{ "id": "about", "label": "About" }]
  }
}
```

`main.js` exports `activate(sketchy)`:

```js
export async function activate(sketchy) {
  sketchy.on('importer', 'scad', async ({ name, bytes }) => ({ parts: [{ name, verts, tris }] }));   // verts: Float32Array, tris: Uint32Array
  sketchy.on('exporter', 'scad', async ({ design }) => ({ filename: design.name + '.scad', mime: 'text/plain', text }));
  sketchy.on('command', 'about', async () => sketchy.ui.toast('Hello'));
}
```

The API: `sketchy.ui` (toast, confirm, form, pickFile), `sketchy.document` (read, addBody), `sketchy.geometry.build(tree)` (a tree of solids, see `src/csg-service.js`), `sketchy.files.save`. Each call needs the matching permission in the manifest: `document.read`, `document.write`, `files.open`, `files.save`, `geometry`.

**Sandbox.** Each add-in runs in a worker inside a sandboxed iframe (`sandbox="allow-scripts"`, no `allow-same-origin`) served by `/addin-sandbox.html` with a policy that allows no network and only its own hashed script. It has no access to the page, your cookies, your designs or the server. Everything it does goes through the app, which checks its permissions on every call. Stopping an add-in removes the frame, which ends even a loop that never finishes.

**OpenSCAD import and export** is built in (`public/addins/openscad/`). It reads the OpenSCAD language with its own interpreter (no OpenSCAD code, MIT licensed): shapes, transforms, booleans, extrusions, hull, minkowski, variables, functions, modules, loops, conditionals and list comprehensions. `text()`, `import()`, `surface()`, `projection()`, `resize()` and `include`/`use` are skipped and listed as warnings. Settings at the top of a script (`width = 40;`) appear in a form before import. Export writes each body as a `polyhedron` module (a snapshot of the shape, not the feature timeline).

## Large designs

Sketchy rebuilds the timeline after each edit, so a design with hundreds of features or very dense meshes can feel slow. What it does about that:

* **Only the changed part is rebuilt.** The kernel keeps checkpoints along the timeline. Editing a feature near the end replays only the steps after the nearest checkpoint (the status line says "from step 224 of 241"); editing the first feature replays everything. Shapes no later step needs are freed as it goes, so memory stays near the size of the result.
* **Big designs rebuild in the background.** When a rebuild takes longer than about 150 ms, rebuilding moves to a worker thread: orbiting, menus and typing stay responsive, a "Rebuilding the design…" bar shows the time, and **Stop** abandons it. Small designs rebuild on the page as before.
* **The viewport only redraws what changed.** A body that did not change keeps its mesh and its edge lines. Picking and hover on bodies over 20,000 triangles go through a spatial tree instead of testing every triangle. While you orbit a model of more than about 250,000 triangles, heavy bodies are drawn from a coarse copy, and the full mesh returns when you stop.
* **Large imports** show what they are doing and can be cancelled. A model of more than 300,000 triangles asks whether to import it as it is or with a **Reduce** step (a normal timeline step, about 250,000 triangles) that you can adjust or suppress.
* **If it is still slow:** roll the timeline marker back, suppress features you are not working on, or keep a big imported mesh in its own design.

## Explaining problems and checking work

* **Failures say what to do.** A feature that cannot be built shows its reason inside its dialog with a hint for the usual fixes, and a red mark on its timeline item. A feature that built but needs a look (a cut that touches nothing, a fillet that lost some edges) gets an amber mark and a warning.
* **Extrude and cut say what they act on.** The dialog shows a line such as "Cuts from Body 2" and outlines the affected bodies in the viewport. Automatic mode says which operation it chose.
* **Lost fillet edges.** If an earlier change makes some picked edges disappear, the fillet or chamfer still builds with the rest and says "1 of 6 picked edges could not be found". The missing edges are drawn in red; **Remove them and pick again** drops them so you can click the new ones.
* **Sketch constraints are solved together** (`src/sketchsolve.js`: damped least squares over every shape's numbers). Chains and loops work (four lines made horizontal and vertical close into a rectangle; parallel pairs plus an equal side make a rhombus). The shape you name first moves to meet the second, sizes and line lengths are kept where the constraints allow, Fix pins what it names, and a size driven by a parameter expression is held. If constraints cannot all hold, the older one-after-another method is used when it leaves less error. Sketches with more than about 360 numbers fall back to the older method.
* **Sketch state.** The sketch palette shows how many of the sketch's numbers are pinned down by dimensions and constraints ("Fully defined", "Partly defined", "Not defined yet"), counted from the solver's degrees of freedom. The tooltip lists what is still free, such as "Rectangle 1 width". Where the first shape sits is not counted.
* **Expressions.** Errors are in plain words and suggest the nearest parameter name ("Did you mean height?"). Right-click a number box and choose **Make this a parameter…** to turn its value into a named parameter.
* **Version compare and restore.** In Version history, **Compare** overlays an older version on the latest: unchanged grey, added blue, removed red, with the volumes and the changed features. **Restore** adds a new version on top ("Restored from V3") and keeps the current one in the history.
* **Export.** The suggested file name is the design name, then the body's name when you export just one body of several ("Bracket_Lid_v3"), then the version. Type your own and it is left alone. 3MF is the default format. Before exporting a mesh the dialog checks watertightness, bed fit, overhangs and wall thickness. They are advice only; you can always export.

## Accounts, storage and versions

* Data lives in the `sketchy-data` volume (`/data`): `users.json` (scrypt-hashed passwords), `sessions.json`, `mcp-tokens.json` (hashed), `settings.json`, `projects/<user-id>/*.json`
* Sessions are `HttpOnly` + `SameSite=Strict` cookies lasting a year (renewed whenever you use the app), and the API requires a custom header, which blocks cross-site requests. Sketchy itself serves plain HTTP, so put it behind HTTPS (a reverse proxy) if you expose it beyond your home network. See [SECURITY.md](SECURITY.md) for exposing it safely, the limits and the settings
* **Version history:** click the **Save** icon (top left, beside the designs button) to save a new version. The Save dialog asks for a version description (pre-filled with "User saved") and shows the number the version will get, which you cannot change. Exported files get the version on the end of the name (`Bracket_v3.stl`). Ctrl+S saves a version without asking for one; only Save makes a numbered revision: autosave and edits made by an AI assistant change the design in place without one. Every save keeps the previous revision under `projects/<user-id>/.versions/<design>/`. Click the **V3 ▾** badge on a design in the sidebar, then **Version history…**, to see each version with its description, open an older one or restore it as the newest (nothing is lost)
* **Recycle bin:** deleting a design moves it, with its versions, thumbnail, folder and any unsaved draft, to the **Recycle bin** at the bottom of the Designs panel. It is kept for 30 days (`BIN_DAYS`, `0` = deleting is permanent), then removed. From the bin a design can be restored (under its old name, or a suggested "Name (restored)" if that name is taken now), deleted for good, or the whole bin emptied. The bin counts toward the storage limit, and when a save would go over it the oldest bin items are removed first. Each account sees only its own bin.
* **Saved kernel cache:** a design that is slow to build (it is built in the background worker) is not rebuilt from nothing each time it is opened. A few seconds after its builds settle, Sketchy saves the kernel's states (the last two and every eighth, with the shapes as OpenCascade BRep text, gzipped, about 0.4 MB for the 41-feature benchmark) as `<design>.cache` next to the design, and reads them back into the worker before the first rebuild. Reopening that design took 0.9 s to the first bodies instead of 1.9 s, and the worker's build 0.2 s instead of 1.4 s. The cache is only a head start: the rebuild compares it with the design and keeps what still fits, a cache from another Sketchy version is ignored, and one that cannot be read is ignored. It is stored per account, counts toward the storage limit and is the first thing removed when space runs short (before the recycle bin), goes with the design when it is renamed or deleted, and is never kept in the recycle bin. `MAX_CACHE_MB` (default 128, `0` = none are kept) limits one design's.
* **Drafts:** an in-progress design is synced to the server so you can resume on another device, and Sketchy warns if the same design changed elsewhere
* Sketchy is meant to run with its server (the Docker image, or `npm run dev`, which starts the same server). Saved designs, folders, version history and drafts all live there. If the server can't be reached, Save falls back to downloading a `.sketchy.json` file, and the last session is restored from browser storage.

## Editing earlier features

Fillets, chamfers, holes, shells and sketches on faces remember what they were attached to, so changing an earlier dimension (a wider box, a taller extrusion) moves them with it. Edges are found again by their position, direction and the two faces they join; faces by their direction and nearest plane. When two candidates are about equally likely the feature reports an error and asks you to reselect, rather than guessing. `npm run test:robustness` checks these cases.

## Known limits

Sketchy has one modelling kernel, a boundary-representation (B-rep) kernel: OpenCascade through replicad. A few operations are still approximate or absent:

* Face-level operations (Draft, Thicken Face, Replace Face, Press/Pull) act on **flat faces** only (Thicken Face and Replace Face), Draft on flat faces, Press/Pull on flat faces.
* **Fillets** have constant or linearly varying radius. There are no setback corners; where fillets meet at a vertex the rounded cuts simply overlap.
* **IGES** export is not offered. STEP export is exact (true planes, cylinders, spheres, fillets). The exceptions are bodies that are meshes: an imported STL/OBJ/3MF is a faceted solid, and so is a body stretched differently along each axis (planar faces stay planar; curved ones become facets, because the OpenCascade build used here does not export the general-transformation class that would stretch them exactly).
* There is **no Split Face** command yet (the kernel has the faces for it). Sketch on the face and extrude or emboss instead.
* A **chamfer** or **fillet** on an edge that runs into a rounded corner is retried as a wedge cut and at smaller sizes; if nothing fits, the error gives the largest size that does. A **Shell** of a body swept or lofted, a pipe (also along a 3D path) or an imported STEP solid is an exact wall: the body less the same sweep or loft with its profile or sections moved in or out (in their own planes, so on a slanted loft the wall is a little thinner across the slope than the stated thickness). Ends that are not opened are closed by caps; with no face picked the whole body is a closed hollow. Walls as thick as the tube radius fail with a message. Bodies from other features (3D-path pipes, imported solids) that OpenCascade cannot offset fall back to a faceted wall, and very large ones refuse it.
* **Sketch on a curved face:** with a curved face picked, Create Sketch places the sketch on the plane that touches the surface at the point you clicked (the surface normal there, interpolated from the smoothed mesh, is the sketch normal; for a cylinder it is the true tangent plane). The plane is fixed once made: it does not follow the face if the face moves. A plane through a cylinder's axis is not offered; make one from two points or an axis in the Construct menu.
* **Surfaces** are faces and shells: there is no surface fillet. **Extend surface** grows every open edge by a strip along the surface's tangent (the strips of neighbouring edges meet only at the corner point). **Thicken** works on flat and curved surfaces (the surface is offset and the walls ruled between the edges); a surface that closes on itself (a full revolve) or whose offset folds over cannot be thickened.
* *To object* extents use the object's bounding box. Booleans are body-to-body.

## The kernel

Every design is built by one kernel: OpenCascade (a boundary-representation kernel) through replicad, in `src/backend-brep.js`, with the shared feature rules in `src/featurespec.js` and the sketch regions in `src/sketch-brep.js`. The 23 MB WebAssembly file (5.9 MB with brotli) is preloaded by the page and fetched when the app starts; the loading screen shows how much has arrived. The server sends it `immutable`, and a service worker (`src/sw.js`, on https or localhost) keeps the app shell and every hashed build file for repeat visits and offline use; it never touches `/api`, `/mcp`, OAuth, add-ins or any authenticated or `no-store` response, and a new version replaces the old files and asks open pages to reload. The kernel is loaded again inside the background worker from the same cached file. OpenCascade's glue uses `new Function`, so the page's content security policy allows `'unsafe-eval'` for scripts (nothing else was loosened).

* **Timeline.** `rebuild(features, count, opts)` replays the features. Each step is kept, so a change to feature k replays only features k..end (the incremental cache); a slow rebuild moves to a background worker with a busy bar and **Stop**. Measured with `node scripts/bench-brep.mjs` on a 41-feature design: a full rebuild about 1.0 s, an edit of the last feature about 0.3 s (27 ms inside the worker), an edit near the start about 1.0 s. A feature that cannot be built reports an error on that feature and the rest of the design still builds.
* **Meshes.** Each body is tessellated once per shape (the gap allowed between surface and triangles is 0.15 % of the part's diagonal, within 0.04 to 0.6 mm, and no triangle turns more than 0.3 rad from its neighbour) and every triangle knows its B-rep face (`faceOf`, `faces`). A mesh is for drawing, picking, export of STL/3MF/OBJ and the print checks; it is never the model.
* **Faces.** A click selects the whole B-rep face, curved or flat. A stored face (an Appearance in `doc.faceAppearance`, or a face picked for Shell, Draft, Hole, Press/Pull) keeps a `brepFace` key (surface type, area-weighted centre, area); `src/brepface.js` finds the face again after an edit that moves or resizes it (same type and normal, nearest centre, clearly the best candidate) and the point-and-normal match is the fallback.
* **Imported meshes** (STL, OBJ, 3MF) are welded, repaired, then **sewn into a faceted solid**: coplanar neighbours become one planar face (`src/sew.js`). Sewing costs about 0.2 ms per face and more as it grows, so a mesh of more than 32,000 flat faces cannot be sewn. A model is always imported: one of more than 30,000 triangles is **simplified by default** to about 20,000 (quadric edge collapse, `src/meshtools.js`), without a question, and if the result still has too many faces the import simplifies harder, up to five more times. The message says what it was simplified from, and the Reduce setting of the import step holds the amount, so it can be changed later. Clean Mesh, Reduce and Separate work on the triangles of a body and sew the result. **STEP files import as true B-rep** (the `importstep` feature keeps the file's surfaces).
